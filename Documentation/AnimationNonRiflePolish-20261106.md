# 棍与双刀动画微调（接续枪械微调）

本轮实际修改 `Assets/Game/Prefabs/Characters/Sahur/Scripts/SahurAttack.cs`，两项改动均使用现有片段、动画层与遮罩。上一轮枪械修改保留。本轮没有改角色移动参数、伤害、命中窗口、敌人动画或场景资源。

## 实际修改和前后参数

| 项目 | 修改前 | 修改后 | 原因 |
|---|---|---|---|
| 棍：从移动进入上身轻攻击层 | 起手直接把权重设为 1 | 起手保留当前权重，按 1 / 0.06s 的速率升到 1 | 隐藏层可能仍停在上一招姿势，直接启用会让手臂跳变；新权重在起手阶段进入 |
| 棍：轻攻击层退出 | 0.18s | 0.18s，保持 | 保留原收招 |
| 棍：原有片段间 CrossFade、攻击时钟 | 原 blend 参数、offset=0 | 保持 | 不推迟命中或重新播放连击 |
| 双刀：移动冲刺收招切层当帧 | `Animator.Play` 后立即读取尚未更新的层状态，可能立即 FinishAttack | 保存源进度，当帧读保存值，下一帧继续检查 Animator | 恢复原来已经存在的上身收招，避免收招在切层当帧被误清除 |
| 双刀：收招开始 | 冲刺窗口末端 .56 + .035 | .595，保持 | 不改变原设计接管时机 |
| 双刀：脚步回到 Locomotion | CrossFade 0.10s | 0.10s，保持 | 走跑仍可接管下身 |
| 双刀：上身收招退出 | normalizedTime .8–.98 的 SmoothStep | 保持 | 保留原来的渐隐与结束条件 |
| Animator Controller 转场、BlendTree、剪辑和播放速度 | 原资源值 | 全部保持 | 本轮只修正脚本驱动的层权重与交接读取 |

修改前的原生控制器、层、状态、过渡值和角色配置见 `AnimationNonRifleReview/audit-before.json`。完整源码副本在 `.codex/animation-nonrifle/source-before/`，其中 `SahurAttack.cs` 可单独用于撤销本轮生产改动；不要覆盖其他已修改文件。

## 证据与验证

- 60Hz 同输入回放，移动棍起手的右上臂最大单帧局部旋转由 **53.55° 降到 13.39°**。该数字仅适用于这组回放；查看了前后原生帧，起手逐步进入原姿势。原命中窗口开始时上身层权重已达到 1。
- 双刀修复前的三个连续移动蓄力攻击都在交接时丢失收招；修复后 30 / 60 / 120Hz 每组连续三次均保留原收招。60Hz 进度从 .57778 连续进入 .60，没有重置到 0 或读取上次动作结尾。查看了原生收招帧，下身能回到移动，上身保留原双刀姿态。
- **79 项原生 Play Mode 脚本检查通过**：三种帧率的棍/双刀交接，走跑启停、急转、斜向速度、跳跃落地、翻滚、棍/双刀三连、移动攻击、蓄力、旋转、双刀格挡、投棍返回、两种武器空中攻击、枪械回归，以及双刀收招中的合法闪避、换武器与游泳接管清层。
- 起步仍为 1 帧；达到九成走速约 116.7ms，停止约 100ms，移动落地恢复约 150ms，与前一轮相同。
- **340 项资源契约检查通过**，包括原动作名称、基础播放速度、遮罩和脚本引用。Unity 重新编译成功，无编译错误。Test Runner 发现 EditMode / PlayMode NUnit 测试均为 0，因此上述数字是原生回放与资源检查数，不是 NUnit 数。
- 中间 `before` 报告保留了双刀缺失收招的失败证据。`final-exits` 曾把 .60 进度的闪避误设为应立即发生；当时尚未达到原合法取消点。测试修正为等待 `CanDodgeCancel`，没有更改取消时机；`final-exits-legal` 全部通过。
- 最终结果在 `AnimationNonRifleReview/summary.json` 及各项 JSON；原生逐帧数据和截图在 `.codex/animation-nonrifle/`。`after60` 是中间实验，最终生产版本以 `final60 / final30 / final120` 为准。
- 完成后已恢复原工作区场景，Unity 停在编辑模式；玩家存档与本轮开始时逐字节一致。
