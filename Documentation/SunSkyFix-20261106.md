# 岛上白色光球修正

前一版按摄像机移动太阳实体球，仅验证了俯视角的球体位置变化，未完整解决用户随后在游戏画面中看到的白光。这次停用了该世界空间太阳球的 MeshRenderer 和 SphereCollider，并将太阳圆盘移到现有 Procedural Sky 材质中。

太阳圆盘按各相机的观察方向计算，复用天空的太阳方向、云层遮挡和深度测试。只会出现在天空像素中，不再通过移动一个有限距离、高亮的球体模拟太阳。日夜控制仍调用原来的 `SetAtmosphere`；它现在只设置天空圆盘颜色、可见性和亮度，不会重新打开球体。圆盘角半径限制为 0.0065 弧度，亮度上限为 1.5，避免原高亮球体的大片泛光。

修改涉及 `ProceduralSun.cs`、`ProceduralSky.shader`，以及 `OceanWorld.cs` 中零长度太阳方向的回退判断。保留原序列化字段和场景对象，无新增材质实例或相机渲染事件。旧的 `VerifySunCamera` 临时位置桥接已退役，改用 `VerifySunSky`。

Unity 编译通过。[原生 GPU 渲染验证](SunSkyReview/validation.json)通过：两个不同相机位置均有 42 个圆盘变化像素；不透明遮挡物覆盖太阳方向时变化像素为 0；关闭圆盘可见性时变化像素为 0；原球体渲染和碰撞均关闭；天空着色器错误为 0。

[第一岛实景复查](SunSkyReview/island-after.png)使用当前场景的 Game 类型相机直接渲染，画面未见岛上光球。这次未进入 Play 模式执行完整 Boss 战，未写入生产场景或玩家存档。后续如仍出现不同形状或位置的白光，应另行隔离来源，不直接归因于太阳。

## 随后发现的运行时天空发白

用户随后提供的仰视游戏画面暴露了未被前一轮静态截图覆盖的问题：`OceanWorld.cachedSun` 实际缓存成了 `Bounded contact bounce light 1`，类型为 Point，而非 `Directional Light`。原逻辑只在缓存为空或对象不活跃时重找；特效灯对象仍活跃，所以天空的 `_SunDirection` 一直没有更新，为零向量。原着色器先 normalize 再检查零值，无法可靠防止无效结果，新圆盘计算也受到影响。

已在不中断 Play 的情况下修复当前缓存并恢复蓝天，同时保存两项永久修改：只缓存启用的 Directional 灯，并重新验证缓存类型；着色器在归一化前检查太阳/月亮向量长度，为零值和极小值提供有限回退方向，圆盘边缘宽度也设有非零下限。太阳方向增加有效的材质默认值。

[运行画面之前](SunSkyReview/sky-before.png) · [运行画面之后](SunSkyReview/sky-after.png)。同一运行会话、同一相机姿态，没有退出 Play 或重置玩家。

[强制方向回归](SunSkyReview/direction-validation.json)在当前运行关卡渲染正常、零和极小向量三种输入，均通过：非有限像素 0，顶部约 88,855 个像素保留蓝色天空，裁切至纯白的天空像素 0，着色器错误 0。完整 C# 源码及其采样依赖通过独立 dry-run 编译检查；为保持用户当前运行状态，未强制进行会重启脚本域的项目编译。永久 C# 修改将在下一次正常项目编译时载入；当前缓存与天空着色器已即时修正。
